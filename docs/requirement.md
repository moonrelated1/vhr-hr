## 1. 引言

### 1.1 编写目的

本文档定义智汇人力资源管理系统「员工管理模块」的功能需求、数据需求与非功能需求，作为后续概要设计、详细设计、编码实现、测试用例编写与最终验收的共同依据。

预期读者：项目组成员、课程指导教师、验收评审人员。

### 1.2 项目背景

本项目为《软件工程实践》课程作业。项目基于开源脚手架 `lenve/vhr2.0` 进行二次开发，脚手架已提供登录鉴权、权限管理、菜单管理、部门/职位/职称等基础能力。

脚手架中 `vhr-employee`（员工管理）模块为**空模块**，仅创建了目录结构，未编写任何业务代码。本模块的全部功能由本项目组自行设计并实现，是本项目的核心增量之一。

## 2. 项目概述

### 2.1 项目目标

为企业 HR 人员提供一套完整的员工信息管理工具，实现员工从**入职建档**到**在职期间异动记录**的全过程数字化管理，替代传统 Excel 分散管理方式。

### 2.2 模块范围

本模块包含 **7 个功能页面**，按系统导航分为两组：

**（一）员工资料**

| 编号 | 页面 | 前端路由 | 说明 |
|---|---|---|---|
| P1 | 基本资料 | `/employee/basic` | 员工核心档案的增删改查 |
| P2 | 高级资料 | `/employee/advanced` | 在基本资料基础上维护下属记录 |

**（二）人事管理**

| 编号 | 页面 | 前端路由 | 对应数据表 |
|---|---|---|---|
| P3 | 员工资料 | `/personnel/emp` | `employee` |
| P4 | 员工奖惩 | `/personnel/ec` | `employeeec` |
| P5 | 员工培训 | `/personnel/train` | `employeetrain` |
| P6 | 员工调薪 | `/personnel/salary` | `adjustsalary` |
| P7 | 员工调动 | `/personnel/remove` | `employeeremove` |

> **不在本版本范围内**：薪资核算（工资账套、工资表、月末处理）、统计管理、系统管理。
> 其中薪资管理模块计划作为本项目的第二个增量模块，另立需求文档。

### 2.3 用户角色与权限

| 角色 | 说明 | 本模块权限 |
|---|---|---|
| 系统管理员 | 拥有全部菜单权限 | 全部功能的增、删、改、查 |
| 人事专员 | 负责员工日常管理 | 员工信息的增、改、查；无删除权 |
| 普通员工 | 仅可查看本人信息 | 只读 |

> 权限由脚手架已有的角色-菜单体系控制，本模块只需在菜单表中登记对应 URL。

### 2.4 运行环境

| 项目 | 要求 |
|---|---|
| 服务端 | JDK 17+、MySQL 8.0+ |
| 客户端 | Chrome / Edge 等现代浏览器 |
| 分辨率 | 建议 1366×768 以上 |

## 3. 功能需求

### 3.1 功能结构

```
员工管理模块
├── 员工资料
│   ├── 基本资料（档案增删改查、搜索、导出）
│   └── 高级资料（奖惩 / 培训 / 调动 / 调薪 记录维护）
└── 人事管理
    ├── 员工资料（按部门、姓名等维度检索）
    ├── 员工奖惩
    ├── 员工培训
    ├── 员工调薪
    └── 员工调动
```

### 3.2 员工基本资料管理（FR-EMP）

#### FR-EMP-01 员工档案分页查询　【优先级：高】

- **描述**：以表格形式分页展示员工档案列表。
- **输入**：页码、每页条数。
- **输出**：员工列表（工号、姓名、性别、出生日期、所属部门、职位、职称、聘用形式、入职日期、在职状态）。
- **业务规则**：
  1. 默认每页 10 条，支持 5/10/20/50 切换。
  2. 列表项须展示关联字典表的**名称**而非 ID（如「所属部门」显示部门名，不显示部门编号）。
  3. 在职状态须以不同颜色标签区分（在职 / 离职）。

#### FR-EMP-02 条件搜索　【优先级：高】

- **输入**：姓名（模糊）、所属部门（下拉）、职位（下拉）、职称（下拉）、聘用形式（下拉）。
- **输出**：满足全部条件的员工列表。
- **业务规则**：
  1. 多个条件为**逻辑与**关系。
  2. 姓名为**模糊匹配**，其余为精确匹配。
  3. 条件可任意组合，也可全部为空（等价于全量查询）。
  4. 搜索后结果重新分页，页码重置为第 1 页。

#### FR-EMP-03 新增员工　【优先级：高】

- **输入**：见下表字段。
- **输出**：新增成功后员工列表刷新，总数 +1。
- **业务规则**：
  1. 工号 `work_id` **必填且全局唯一**，重复时报错「该工号已存在」。
  2. 身份证号 `id_card` 为 18 位，须校验格式合法性。
  3. 手机号 `phone` 为 11 位数字。
  4. 邮箱 `email` 须符合邮箱格式。
  5. 部门、职位、职称、民族、政治面貌从字典表下拉选择。
  6. 入职日期不得晚于当前日期。
- **字段清单**：

| 字段 | 说明 | 必填 | 校验规则 |
|---|---|---|---|
| name | 姓名 | 是 | 长度 ≤ 10 |
| gender | 性别 | 是 | 男 / 女 |
| birthday | 出生日期 | 是 | 日期格式 |
| id_card | 身份证号 | 是 | 18 位 |
| wedlock | 婚姻状况 | 否 | 已婚 / 未婚 / 离异 |
| nation_id | 民族 | 否 | 字典表 |
| native_place | 籍贯 | 否 | 长度 ≤ 20 |
| politic_id | 政治面貌 | 否 | 字典表 |
| email | 邮箱 | 否 | 邮箱格式，长度 ≤ 20 |
| phone | 电话 | 否 | 11 位数字 |
| address | 联系地址 | 否 | 长度 ≤ 64 |
| department_id | 所属部门 | 是 | 字典表 |
| job_level_id | 职称 | 是 | 字典表 |
| pos_id | 职位 | 是 | 字典表 |
| engage_form | 聘用形式 | 是 | 劳动合同 / 劳务合同 |
| tip_top_degree | 最高学历 | 否 | 枚举 |
| specialty | 所属专业 | 否 | 长度 ≤ 32 |
| school | 毕业院校 | 否 | 长度 ≤ 32 |
| begin_date | 入职日期 | 是 | 不得晚于今日 |
| work_state | 在职状态 | 是 | 在职 / 离职 |
| work_id | 工号 | 是 | 唯一，8 位 |
| contract_term | 合同期限 | 否 | 数值 |
| conversion_time | 转正日期 | 否 | 日期 |
| begin_contract | 合同起始日期 | 否 | 日期 |
| end_contract | 合同终止日期 | 否 | 不早于起始日期 |

#### FR-EMP-04 修改员工　【优先级：高】

- **描述**：编辑已有员工档案。
- **业务规则**：
  1. 工号 `work_id` 允许修改，但仍须保持唯一。
  2. 表单默认回填该员工现有数据。
  3. 修改后列表须立即反映最新值。

#### FR-EMP-05 删除员工　【优先级：中】

- **描述**：删除员工档案。
- **业务规则**：
  1. 删除前须弹出二次确认。
  2. 若该员工存在奖惩 / 培训 / 调动记录，**不允许直接删除**，须提示「请先处理该员工的关联记录」。
  3. 提示语须包含待删除员工的姓名，防止误删。

#### FR-EMP-06 导出员工数据　【优先级：低】

- **描述**：将当前查询结果导出为 Excel 文件。
- **业务规则**：
  1. 导出内容与当前**筛选条件一致**，而非全量。
  2. 列名使用中文表头。

### 3.3 员工高级资料管理（FR-ADV）

#### FR-ADV-01 查看员工下属记录　【优先级：中】

- **描述**：在员工列表中选中某员工后，以标签页形式展示其奖惩、培训、调动、调薪记录。
- **业务规则**：无记录时显示「暂无数据」空状态，而非空白页。

#### FR-ADV-02 维护下属记录　【优先级：中】

- **描述**：在高级资料页直接新增 / 删除下属记录，无需跳转到人事管理页。
- **业务规则**：新增记录时 `eid`（员工编号）自动绑定为当前选中的员工，用户无需也不能手填。

### 3.4 员工奖惩管理（FR-EC）

#### FR-EC-01 奖惩记录查询　【优先级：中】

- **输入**：员工姓名、奖罚类别。
- **输出**：奖惩记录列表（员工姓名、奖罚日期、奖罚原因、奖罚分、奖罚类别、备注）。

#### FR-EC-02 新增奖惩记录　【优先级：中】

| 字段 | 说明 | 必填 | 校验规则 |
|---|---|---|---|
| eid | 员工 | 是 | 从员工列表选择 |
| ec_date | 奖罚日期 | 是 | 日期格式 |
| ec_reason | 奖罚原因 | 是 | 长度 ≤ 255 |
| ec_point | 奖罚分 | 是 | 整数 |
| ec_type | 奖罚类别 | 是 | 0 = 奖，1 = 罚 |
| remark | 备注 | 否 | 长度 ≤ 255 |

- **业务规则**：列表中 0 显示为「奖」（绿色标签），1 显示为「罚」（红色标签）。

#### FR-EC-03 删除奖惩记录　【优先级：低】

- **业务规则**：须二次确认。

### 3.6 员工调动管理（FR-MV）

#### FR-MV-01 调动记录查询　【优先级：中】

- **输出**：调动记录列表（员工姓名、调动后部门、调动后职位、调动日期、调动原因、备注）。

#### FR-MV-02 新增调动记录　【优先级：高】

| 字段 | 说明 | 必填 | 校验规则 |
|---|---|---|---|
| eid | 员工 | 是 | 从员工列表选择 |
| after_dep_id | 调动后部门 | 是 | 字典表 |
| after_job_id | 调动后职位 | 是 | 字典表 |
| remove_date | 调动日期 | 是 | 日期格式 |
| reason | 调动原因 | 是 | 长度 ≤ 255 |
| remark | 备注 | 否 | 长度 ≤ 255 |

- **业务规则（重要）**：调动记录保存成功后，须**同步更新** `employee` 表中该员工的 `department_id` 与 `pos_id`，使员工档案与调动记录保持一致。该操作须在同一事务内完成，任一步骤失败则整体回滚。

#### FR-MV-03 删除调动记录　【优先级：低】

- **业务规则**：仅删除记录本身，**不**回滚员工档案中的部门与职位。

## 4. 数据需求

### 4.1 本模块涉及的数据表

| 表名 | 说明 | 初始化数据量 |
|---|---|---|
| `employee` | 员工主档案 | 617 条（脚手架自带） |
| `employeeec` | 员工奖惩记录 | 0 条（**需自行构造测试数据**） |
| `employeeremove` | 员工调动记录 | 0 条（**需自行构造测试数据**） |
| `employeetrain` | 员工培训记录 | 0 条（**需自行构造测试数据**） |
| `adjustsalary` | 员工调薪记录 | 0 条（**需自行构造测试数据**） |

### 4.2 字典类表（只读引用）

| 表名 | 说明 | 数据量 |
|---|---|---|
| `department` | 部门（树形结构） | 17 |
| `position` | 职位 | 6 |
| `joblevel` | 职称 | 8 |
| `nation` | 民族 | 56 |
| `politicsstatus` | 政治面貌 | 13 |

### 4.3 实体关系

```
                    ┌──────────────┐
                    │  department  │
                    └──────┬───────┘
                           │ N
                           │
┌───────────┐ 1          N │        ┌──────────┐
│  nation   ├──────────────┤        │ position │
└───────────┘              │        └────┬─────┘
┌───────────────┐          │ N           │ N
│politicsstatus ├──────────┤             │
└───────────────┘          ▼             ▼
                    ┌──────────────────────────┐
                    │        employee          │
                    │      （员工主档案）        │
                    └────────────┬─────────────┘
                                 │ 1
                                 │
              ┌──────────┬───────┴───────┬──────────────┐
              │ N        │ N             │ N            │ N
        ┌─────▼────┐ ┌───▼──────┐ ┌──────▼─────┐ ┌──────▼──────┐
        │employeeec│ │employee  │ │employee    │ │adjustsalary │
        │  奖惩    │ │  train   │ │  remove    │ │   调薪      │
        └──────────┘ │  培训    │ │   调动     │ └─────────────┘
                     └──────────┘ └────────────┘
```

**关系说明**

| 关系 | 基数 | 说明 |
|---|---|---|
| employee → department | N : 1 | 一名员工属于一个部门 |
| employee → position | N : 1 | 一名员工担任一个职位 |
| employee → joblevel | N : 1 | 一名员工对应一个职称 |
| employee → employeeec | 1 : N | 一名员工可有多条奖惩记录 |
| employee → employeetrain | 1 : N | 一名员工可有多条培训记录 |
| employee → employeeremove | 1 : N | 一名员工可有多条调动记录 |
| employee → adjustsalary | 1 : N | 一名员工可有多条调薪记录 |

### 4.4 数据完整性要求

1. 所有子表通过外键 `eid` 关联 `employee.id`，**不得存在孤立记录**。
2. 删除员工前须校验其是否存在子表记录。
3. 字典表数据由系统管理模块维护，本模块**只读**。

## 5. 非功能需求

### 5.1 性能需求

| 编号 | 要求 |
|---|---|
| NFR-01 | 员工列表分页查询响应时间 ≤ 2 秒（617 条数据量下） |
| NFR-02 | 新增 / 修改操作响应时间 ≤ 2 秒 |
| NFR-03 | 列表查询须在数据库层分页，不得一次性查询全表后在内存分页 |

### 5.2 安全需求

| 编号 | 要求 |
|---|---|
| NFR-04 | 未登录用户访问任何接口须返回未授权错误 |
| NFR-05 | 接口层须校验权限，不能仅靠前端隐藏按钮 |
| NFR-06 | 数据库密码等敏感配置**不得写入代码仓库** |
| NFR-07 | 所有数据库操作使用参数化查询，防止 SQL 注入 |

### 5.3 可用性需求

| 编号 | 要求 |
|---|---|
| NFR-08 | 表单校验失败时，错误信息须定位到具体字段 |
